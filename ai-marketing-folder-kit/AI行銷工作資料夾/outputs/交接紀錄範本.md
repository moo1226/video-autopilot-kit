# 交接紀錄範本

> 用途：工作中斷、換人接手、或換到新的 AI 對話時填寫。
> 原則：寫事實與狀態，不寫推測；不放個資與內部資料。
> 建議篇幅：主要四欄合計 80～150 字。

---

## 基本資訊

| 項目 | 內容 |
|---|---|
| 交接日期 | |
| 交接人 | |
| 接手人 | |
| 專案名稱 | |
| 相關檔案 | （列出 outputs/drafts/ 中的檔名） |

---

## 四欄摘要（必填）

### 1. 目標
（這項工作要完成什麼）

### 2. 已完成
（列出已完成且已驗收的項目）

### 3. 關鍵限制
（必須遵守的條件、尚未取得的資料、不能做的事）

### 4. 下一步
（接手人第一件要做的事，越具體越好）

---

## 補充（選填）

- 待補資料清單：
- 待確認事項與負責人：
- 給 AI 的接續指令（可直接貼到新對話）：

```
請先閱讀以下交接紀錄，再依專案指引繼續工作：〔貼上本紀錄〕
```

---

## 填寫示例【虛構示例】

| 項目 | 內容 |
|---|---|
| 交接日期 | 2099-01-10 |
| 交接人 | 承辦人 B |
| 接手人 | 承辦人 D |
| 專案名稱 | 職場英語會話 B1（虛構）課程頁文案 |
| 相關檔案 | `drafts/示例草稿_職場英語會話B1.md` |

- **目標**：完成課程頁 SEO 文案定稿，供網站上架。
- **已完成**：草稿 v1 已產出，QA 的 A、C、E 類已通過。
- **關鍵限制**：開課日期與費用尚待主管 C 確認，確認前不可上架。
- **下一步**：取得日期與費用後，更新草稿中 2 處【待補】，再跑一次 B 類驗收。
